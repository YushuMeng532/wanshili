## 1. 目标与本期范围
<!-- chapter-id: scope -->

网页试用版使用当前浏览器保存数据，支持普通日程、正计时、倒数日、公历生日、循环及修改删除。工作台用于查看原型与产品规则。

V0.6 优先做 AI 语音录入、月末习惯回顾及配套统计。邮箱注册、登录与 MySQL 云同步排在 P1，本版明确规则并提供可交互原型。

## 2. 月历与当天事项
<!-- chapter-id: calendar -->

周一为周首，打开当前月，区分今天与选中日；支持切月和回今天。点击日期展示当天面板，关闭后保留选中日。新建事项带入选中日期。

| 类型 | 日历标记 | 选中日期下方的事项 |
| --- | --- | --- |
| 正计时 | 进行中只标记开始日。结束后标记开始日和结束日，同一天只标记一次 | 从开始日起按选中日累计。选中结束日显示「已结束 · 共 N 天」，结束日之后不再展示 |
| 倒数日 | 只在对应目标日倒数归零时标记 | 其他选中日期也展示倒数；目标日前显示还有N天，目标日显示就是今天，目标日后显示已过N天 |
| 公历生日 | 在对应生日日期标记 | 该日期展示生日事项 |

天数统一跟随选中日期，不固定以真实今天计算。日历标记与下方列表分别计算，列表有事项不代表该日一定有标记。

公历2月29日不生成事项和计划实例，其余闰年日期正常。自然日差值仍按真实公历计算。

## 3. 新建与循环
<!-- chapter-id: create -->

名称去首尾空白后必填，备注选填。正计时用于纪念日，新建时只选开始日期。进行中可从事项详情手动结束。生日默认每年重复，当前只提供公历有效保存；农历明确标记暂未接入。

倒数日可选择仅一次、每天、每周、每月、每年、仅工作日、仅周末。每周至少选一天；每月日期不足时按该月最后一天生成；29、30、31日均适用。若回退结果落在2月29日，跳过该次。每年2月29日同样跳过。工作日选项提示调休日历未接入，不能用周一至周五代算。

循环的持续次数按有效计划出现次数计算；月末回退算1次，跳过2月29日不占次数。仅一次的计划出现次数固定为1。正计时不提供这个选项，其自然日累计不受次数控制。

| 动作 | 行为 |
| --- | --- |
| 子层选择后点完成 | 仅更新主表单草稿 |
| 子层取消或关闭 | 保留打开子层前的值 |
| 主表单未点保存 | 不修改原事项 |
| 空名称保存 | 显示错误边框和请填写事项名称，保留其他填写内容 |
| 保存中 | 显示保存中并拒绝重复提交 |
| 保存失败 | 保留草稿与原事项，允许重试 |
| 取消有改动的表单 | 提供继续编辑和放弃修改 |

### 普通日程

普通日程适用于上课、例会等按计划发生的事项。新建事项的类型栏增加「普通日程」。名称必填，日期默认带入月历选中日，备注选填。循环默认「仅一次」，可改为每天、每周、每月、每年或仅周末。工作日选项沿用调休日历未接入的提示。选择循环后可设持续次数，按有效计划出现次数计算。选「仅一次」时固定为 1 次。

| 用户动作 | 产品行为 |
| --- | --- |
| 保存普通日程 | 在计划发生的日期标记月历，并在选中这些日期时显示当天事项。列表只显示事项信息，不显示正计时或倒数。 |
| 查看过去日期 | 所选范围内的过去计划自动计为已发生，合计按日期去重。 |
| 修改或删除 | 编辑和删除均支持单次操作。删除时可以保留历史，也可以选择「整个系列（含历史）」一次删除完整系列。非循环日程只有一个计划实例。 |

## 4. 详情、编辑与删除
<!-- chapter-id: edit-delete -->

详情展示类型、日期、天数或循环、AI开关与备注。移除所有由用户选择已发生、未发生、未记录的按钮。日期早于真实今天的日程统一为已发生；今天在进入次日后自动计入。原先的未发生选择不再参与新版本判断。

从开始日期的第二天起，已创建事项不可更改类型；界面显示不可用说明。其余字段仍可通过保存和范围选择更新。已有历史分段中的开始日期同样参与类型锁定，不能通过改日期绕过限制。

| 范围 | 修改 | 删除 |
| --- | --- | --- |
| 仅这一次 | 覆盖选中日的单次配置 | 只取消选中日计划 |
| 这次及之后 | 覆盖选中日起的未过去计划 | 取消选中日起的未过去计划 |
| 整个系列（编辑）／全部未发生计划（删除） | 覆盖全部未过去计划 | 取消今天及今后的所有计划，保留历史 |
| 整个系列（含历史） | — | 删除该系列的历史记录及全部未来计划，更新统计 |

选择范围后还需确认。删除完整系列时，界面显示会同时删除历史并更新统计的提示，确认按钮写明「确认删除全部」。只剩历史的系列也可以清除，默认不会选中这个范围。取消保留原数据。

过去的普通循环日程默认选「仅这一次」，可补改名称、日期、备注或删除该次。改期遇到新日期已有同系列计划时，提示另选日期。历史统计随补改和补删更新。选择未来范围时保留已发生的记录。循环事项若选中日已过去，「这次及之后」从今天生效。对循环倒数日，列表中的倒数是到期日的预览，「仅这一次」操作指向确认框显示的那次到期计划。目标已过去时不可单次操作。

仅一次的倒数日按独立事项处理。无论从哪个日期看到倒数，确认框均显示事项名称和目标日。确认删除会取消该目标日，并从今天起移除这条倒数。目标日已过去时保留历史。取消确认保留原数据。

编辑循环事项的「这次及之后」或「整个系列」时，表单中的持续次数是该事项的计划总次数。剩余次数等于总次数减去修改起点之前仍保留的计划次数，最低为 0。取消的计划不占次数，已改期的计划按实际日期计算，同一日算 1 次。只改频率会沿用原总次数。例：设为 5 次且起点前已有 3 次，改成每周一后再安排 2 次。改总次数为 7 次，则再安排 4 次。确认框显示剩余次数。切换为「仅一次」时，将新的单次计划按日期保存，原历史仍保留。

### 手动结束正计时

| 操作或状态 | 产品行为 |
| --- | --- |
| 查看今天正在进行的正计时 | 从今天的事项列表打开详情，显示「结束正计时」次级操作。查看其他日期、尚未开始或已结束的事项时不显示该入口。 |
| 点击「结束正计时」 | 打开确认弹层，显示设备本地的当天日期及最终天数，并提示「结束当天计入天数，历史记录会保留。」 |
| 取消或关闭弹层 | 返回原详情，继续计时。 |
| 点击「确认结束」 | 将设备本地的当天日期记为结束日，返回已结束的事项详情。结束是独立操作，无需选择编辑或删除范围。 |
| 查看已结束的详情 | 显示「已结束 · 共 N 天」、开始日期、结束日期和备注。历史日期下方仍显示选中日对应的第 N 天。 |

开始日和结束日均计入最终天数。以 11 月 17 日开始、11 月 23 日结束为例，最终为 7 天。同一天开始并结束为 1 天。结束操作保留历史记录，结束日之后不再累计。

## 5. 统计
<!-- chapter-id: statistics -->

从「我的 → 统计」进入。入口说明为「查看指定日期范围内的日程天数」。首次进入默认选「本月」和「按类别」。切换查看方式时保留日期范围，切换范围时保留查看方式。从明细返回时恢复原列表和筛选。

| 操作 | 产品行为 |
| --- | --- |
| 本周 | 取设备当地时间所在周的周一至周日，可跨月、跨年。 |
| 本月 | 取设备公历当前月的首日至月末。 |
| 指定日期范围 | 用户选开始日和结束日，两端都包含，支持单日、跨月和跨年。结束日早于开始日时提示调整。点「应用」才更新统计，取消时保留原范围。 |
| 查看合计 | 页面同时展示所选区间和实际计入区间。按设备当地日期，只纳入早于今天的有效计划。所选范围全在今天或未来时显示 0 天，并说明今天及未来还未计入。 |
| 按类别 | 展示普通日程、倒数日、正计时、生日各自的天数。点击类别查看该类别下的具体日程及天数，继续点击可查看计入日期。 |
| 按日程 | 列出区间内有过计划的每个具体日程及其天数。点击「运动」等任一行，查看该日程计入的日期。历史日程同样可查。若区间内没有已发生的日程，显示空状态。 |

同一日程或系列同一天计 1 天，单次调整按调整后的计划日期统计。改名、改期保留原日程或系列的标识。独立创建的同名日程分行显示，用类别、日期或循环规则区分。类别天数为该类别实际日期去重后的天数，总天数对所有类别再按日期去重。例：4 月 8 日同时有「运动」和「复习」，两个日程各计 1 天，普通日程及总天数在这一天均只计 1 天。

普通日程和生日按有效计划日期统计。倒数日按目标日或循环归零日统计。正计时从开始日算起，已结束的计至结束日，开始和结束同日计 1 天。只要仍处于有效区间，正计时中间的日期也可计入。所有类别跳过 2 月 29 日。删除未来计划后，过去已发生的日期继续保留。计算时汇总所选区间内有效日程，避免为每个日期反复回算整个循环。

统计覆盖当前设备或账号可读取的日程。AI 习惯回顾使用另一次按自然月的汇总，仅纳入已授权的日程。统计页选「本周」或指定区间也可以进入自然月回顾。

演示路径为「指定日期范围 → 4 月 8 日至 19 日 → 应用 → 按日程 → 运动」，明细显示 3 天及对应日期。[Figma 统计演示](https://www.figma.com/proto/8aE2Z9hUhKtxgXjnEuCY7I?node-id=230-2255&page-id=230%3A847&starting-point-node-id=230%3A2255&scaling=scale-down)

## 6. 本版改动与已确认边界
<!-- chapter-id: release -->

已确认：纪念日计时、选中日计算、月末回退、仅跳过2月29日、编辑和删除范围、可选历史保留、类型锁定、自动发生、删除人工确认按钮。

网页试用版支持基础日程和按日期范围统计，读取当前浏览器中的日程。网页通过 AI 助手 解析中文日程并生成习惯总结。支持听写的浏览器可先把语音转为文字，用户核对后提交。账号登录、云同步和 Figma 原型使用预设示例。

公开试用版升级时自动迁移可读取的旧版日程和设置，保留旧数据。遇到不支持的版本、格式错误或写入失败，提示原因并提供本地备份导出。首次打开且没有旧数据时展示示例。「恢复示例」需确认，恢复前的日程进入本地备份。

多个标签页同时编辑同一事项时，提示关闭其中一个标签页后继续。不同事项和设置可分别操作，每次保存合入最新数据，先后保存的修改都应保留。恢复示例后，其他标签页里基于旧数据打开的表单必须重新打开。

## 7. AI 语音创建和管理日程（P0）
<!-- chapter-id: voice -->

在日历页点底部中央的「＋」，可在弹层中选择「手动创建」或「AI 语音」。手动创建进入原有表单。AI 语音按麦克风授权、中文录音、转写核对、AI 解析、用户确认的顺序进行。

| 环节 | 产品规则 |
| --- | --- |
| 听写 | 用户点「开始听写」后请求麦克风权限。听写就绪时显示波形和「可以说话了」。停顿后自动结束并转成文字，开始后约 6 秒未检测到发声也会自动结束。拒绝权限、未听到语音或听写失败时可重试或直接输入。切到后台时停止本次听写。 |
| 核对和解析 | 显示转写状态，完成后允许修改文字或重录。用户点「解析日程」后才把确认过的文字及解释相对日期所需的设备日期和时区发给 AI 助手。已有日程列表和备注留在万事历。录音在本次转写完成或取消后清理临时副本。 |
| 新建和查询 | 支持普通日程、倒数日、正计时和公历生日。预览显示事项字段、绝对日期和星期。缺必要信息时追问，查询跳到对应日期。相对日期依据发送时的设备日期和时区，一周从周一开始。涉及具体时刻时，先请用户确认是否只按日期保存。 |
| 修改和取消 | 在设备或当前账号范围内查找目标。同名结果显示日期和类型，由用户选定。改期展示原日期和新日期。重复事项沿用已有作用范围，结束正计时沿用原确认弹层。历史保留和类型锁定规则照常适用。 |
| 确认和异常 | AI 提供草稿或定位目标，由用户在现有界面确认保存、改期、删除或结束。每次处理一个操作，取消时保留原数据。解析失败保留输入，确认前目标变化或相对日期失效时重新核对。重复提交同一次确认只写入一次。 |

演示用例为 11 月 23 日说「明天交报告」，确认转写后得到 11 月 24 日的普通日程草稿，保存后回到当天日历。 [Figma 语音录入演示](https://www.figma.com/proto/8aE2Z9hUhKtxgXjnEuCY7I?node-id=230-850&page-id=230%3A847&starting-point-node-id=230%3A850&scaling=scale-down)

## 8. 月末习惯回顾（P0）
<!-- chapter-id: habit -->

「我的」提供统计、AI 习惯分析、月末回顾提醒、本机数据、隐私说明及账号入口。全局分析和新事项的单项授权默认关闭。全局关闭时保留单项选择。

| 环节 | 产品规则 |
| --- | --- |
| 月末提醒 | 开启 AI 习惯分析后默认开启月末提醒，用户可单独关闭。按设备公历在每月最后一天触发，包括闰年 2 月 29 日。月末打开、回到前台或应用开着进入月末时显示应用内提醒，同月自动提示一次。选「稍后查看」后仍可从「我的 → 统计」进入。错过月末时，下次只补提示最近一个待回顾月份。 |
| 回顾时间范围 | 月末当天统计从当月 1 日到昨天，下月打开上月回顾可覆盖完整上月。4 月 30 日显示 4 月 1 日至 29 日。提醒触发日与 2 月 29 日日程实例规则独立。 |
| AI 总结 | 只统计已保存且仍授权参与的事项。提醒出现和查看回顾只读本地统计。用户点「生成 AI 总结」后才将各类型去重天数、总去重天数和统计区间发给 AI 助手。AI 整理文字，万事历提供数字。总结描述日程安排，避免将计划日期推断成实际完成。 |
| 空状态与失败 | 没有符合条件的记录时提示空状态，无需发送请求。请求期间避免重复提交。生成失败时保留统计数字并提供重试。撤销相关授权后，清除已生成的受影响总结，尚未返回的结果也不再显示。 |

示例中的 19 天是去重总天数。普通日程 12 天、正计时 8 天、倒数日 3 天、生日 1 天可以互相重叠。[Figma 我的页面](https://www.figma.com/design/8aE2Z9hUhKtxgXjnEuCY7I?node-id=230-2180) · [Figma 月末回顾演示](https://www.figma.com/proto/8aE2Z9hUhKtxgXjnEuCY7I?node-id=230-1997&page-id=230%3A847&starting-point-node-id=230%3A1997&scaling=scale-down)

P0 先在受控试用中验证，日程保存在当前设备。AI 助手 密钥由后端保管，付费调用使用试用授权和额度控制。

## 9. 注册、登录与账号归属（P1）
<!-- chapter-id: account -->

「我的」提供邮箱注册、登录、找回密码和退出。验证邮箱后创建账号，系统分配唯一且固定的账号 ID。邮箱规范化后保持唯一，并发提交同一邮箱只产生一个账号。重复注册引导登录或找回密码。验证链接过期后可重发。

登录后显示该账号的日历、统计与偏好。同一个账号换设备可以读取已同步的数据。退出或切换账号立即清除上一账号的页面数据和账号缓存，云端记录继续保留。会话过期时提示重新登录，重新登录后再核对未提交的改动。所有读写、统计和 AI 取数均依据后端会话确认的账号 ID。

## 10. MySQL 保存与版本兼容（P1）
<!-- chapter-id: cloud-data -->

手机页面请求万事历 API，后端确认账号身份，再连接 MySQL 读写。数据库连接信息放在后端。开发环境与线上环境使用不同的库，同一线上环境的兼容客户端版本共用原有数据库。

| 场景 | 数据规则 |
| --- | --- |
| 账号数据归属 | 用户资料、事项、循环规则、单次例外、历史分段及 AI 偏好按账号 ID 关联。日程和系列保留稳定 ID，名称编辑后统计仍能找到原记录。验证授权后再读写。 |
| 保存和同步 | 以数据库确认成功作为保存成功的依据。网络或数据库失败时保留草稿并提示重试。重复提交同一次操作只写一次。两台设备编辑同一日程时，后一次若基于旧版本，展示冲突并请用户核对新版本再保存。 |
| 升级数据表 | 使用编号迁移记录，线上升级前先试迁移并备份。新增字段优先兼容旧版本。旧页面提交本次改动的字段，由后端校验并保留其他现存字段。线上升级保留已保存的用户数据。 |
| 试用版旧数据 | 首个云端账号从空日历开始，本机试用记录留在原浏览器。后续加导入时由用户确认目标账号，按账号 ID 和本地日程 ID 识别重复，保留循环和历史。 |

验证示例以同一测试账号登录两台设备。第一台保存「运动」后，第二台能看到该日程及其统计。另一账号查不到这条记录。两台设备先后修改同一条旧记录时，第二次保存显示冲突并保留草稿。
