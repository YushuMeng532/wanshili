# 需求与Spec问题：V0.5确认结果

日期：2026-11-19。以下12项已由用户确认，并写入[PRD](modules/01-calendar/prd.md)、[开发说明](modules/01-calendar/dev-spec.md)和[页面设计](modules/01-calendar/page-design.md)。本表替代原先的待确认建议。

| 原问题及影响 | 已确认的处理 |
| --- | --- |
| 1. 原型、前端和产品范围混用，完成标准不一致 | 保留当前前端设计，前端提供本地使用，工作台和Figma展示同一套规则 |
| 2. 日历标记与下方列表混用，事项显示和数字不一致 | 标记与列表分开查询；数字按选中日，倒数日只在归零日标记；正计时只标开始日 |
| 3. 第0/1天与持续次数混淆 | 正计时用于纪念日，当天第1天，按自然日累计；取消循环和持续次数 |
| 4. 子层未保存就改原值 | 完成只更新草稿，取消保留原值，主表单保存才生效 |
| 5. 月末与闰日缺规则 | 29/30/31不足时改月末；仅跳过2月29日，回退到该日同样跳过；其余闰年日期正常 |
| 6. 工作日缺调休来源 | 文档和界面说明调休日历未接入，不代算 |
| 7. 农历模型与换算未定 | 农历暂不处理，保留明确说明 |
| 8. 系列操作范围未定 | 编辑删除均支持仅这一次、这次及之后、整个系列；覆盖对应未过去数据 |
| 9. 删除计划与历史混淆 | 仅这一次只取消选中日，后两种取消对应后续/全部未过去计划；过去历史保留可看 |
| 10. 历史归类和类型修改影响统计 | 开始日期第二天起禁止改类型；过去日程自动已发生，保留历史配置和类型 |
| 11. AI开关被误解为分析已可用 | 只保留开关，不新增AI功能 |
| 12. 版本迁移和多标签冲突未定 | 未上线阶段版本变化清除本应用旧数据；同事项编辑使用独占锁，提示关闭一个标签页后继续 |

统计同步改为过去计划日期的并集，不再依赖人工确认；今天在进入次日后计入。删除人工已发生/未发生/未记录按钮。

## 实现核对

验证结果与各端同步状态见[验证记录](modules/01-calendar/validation.md)。原型中的固定示例不承担运行时本地保存和日期计算；已部署产品前端承担实际规则。
